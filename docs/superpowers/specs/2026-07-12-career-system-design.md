# Career Reflection and Planning System Design

## Purpose

This project should become a long-term career reflection and planning system, not only a personal resume page. The public website presents a polished, safe summary of past experience and current focus. The private `career-vault` keeps the full working notes, project retrospectives, quarterly reviews, planning details, and sensitive evidence.

The system should help answer three recurring questions each quarter:

- What did I do?
- Where did I grow?
- What should I focus on next?

## Confirmed Direction

Use a hybrid structure:

- Public website: organized around a public career timeline, skills and credentials, and current focus areas.
- Private vault: organized around project nodes, quarterly reviews, and planning notes.
- Maintenance rhythm: quarterly reviews plus immediate retrospectives for important projects.

The public website should show past experience and current focus directions only. It should not show detailed future plans, task lists, private reflections, internal links, personal names without permission, salary information, or unpublished evidence.

## Public Website Architecture

The public site remains a static GitHub Pages site generated by Astro. It should be a public-facing career archive and resume extension.

### Career Timeline

The timeline presents selected career stages and important projects. Each public entry keeps the existing public growth structure:

- Background
- Actions
- Results
- Growth

Each entry should include only public-safe fields such as period, role, summary, impact, public evidence, and related skills. The existing bilingual Chinese and English structure should remain.

### Skills and Credentials

Replace the previous abstract capability-theme idea with a practical skills and credentials section. This section helps visitors quickly understand concrete qualifications and working strengths.

Examples:

- Languages: English CET-6, French DELF B2
- Tools: Excel, Python, AI tools, workflow automation
- Work skills: data analysis, project delivery, knowledge management
- Certificates or exams: added later as they become relevant

This section should be structured data, not freeform page copy, so it can be rendered consistently and tested.

### Current Focus

Show two or three current focus themes. Each theme should have a short explanation, but no detailed plans or task lists.

Examples:

- AI-assisted career system: using AI to organize experience, review projects, and identify capability gaps.
- Personal knowledge management: turning project experience and learning material into long-term searchable assets.
- Portfolio and evidence curation: converting public-safe work outcomes into resume and website material.

This section should signal direction without exposing private planning.

## Private Vault Architecture

The private `career-vault` remains separate from the public website. It is the working space for honest reflection, sensitive details, and future planning.

### Project Nodes

Use project nodes for immediate retrospectives after important projects or work events. The existing project-node template should be strengthened to capture:

- Basic information
- Goal and context
- Constraints
- Key actions
- Results and evidence
- What went well
- What was not good enough
- Reusable lessons
- Capability gaps
- Next actions
- Whether a public extract should be created

### Quarterly Reviews

Add a quarterly review template, named by quarter such as `2026-Q3.md`. Each quarterly review should cover:

- What happened this quarter
- Key projects or events
- Growth and skill progress
- Capability gaps revealed
- Next quarter focus
- Public content candidates

Quarterly reviews are private by default. Only stable direction-level focus themes should be extracted into the public site.

### Planning Notes

Add planning notes for detailed future thinking. These can include learning paths, project ideas, certification plans, portfolio plans, and career direction judgments.

Planning notes are never copied directly to the public website. The public site only receives short current-focus summaries derived from them.

## Maintenance Workflow

The recurring workflow is:

1. When an important project or event happens, create a private project node first.
2. At the end of each quarter, write a quarterly review that connects projects, growth, gaps, and next focus.
3. Extract public-safe material into the website only after applying the publication checklist.
4. Update the public website in three places: career timeline, skills and credentials, and current focus.
5. Run tests and build checks before publishing.
6. Push to `main` so GitHub Actions can deploy to GitHub Pages.

## Privacy Boundary

The public website may include:

- Public-safe project summaries
- Public results and non-sensitive evidence
- Skills, credentials, tools, and language qualifications
- Direction-level current focus themes

The private vault keeps:

- Raw reflections
- Detailed planning
- Internal links or documents
- Names of managers, teammates, clients, or interviewers without permission
- Salary, compensation, negotiation notes, or private career constraints
- Unpublished data, credentials, screenshots, or sensitive evidence
- Detailed future timelines and task lists

## Technical Scope for the First Implementation

The first implementation should stay small and static. Do not add login, databases, CMS features, online editing, or a backend.

Recommended changes:

- Add structured data for skills and credentials.
- Add structured data for current focus themes.
- Update the homepage to render career timeline, skills and credentials, and current focus.
- Add private vault templates for quarterly reviews and planning notes.
- Strengthen the private project-node template.
- Update project documentation to explain the public/private workflow.
- Add focused tests for the new public data structures where useful.

## Validation

Before claiming the first implementation is ready:

- Run `pnpm test`.
- Run `pnpm build`.
- Confirm Chinese and English career entries remain paired by slug.
- Confirm public data does not include private-only fields.
- Confirm the homepage renders the three intended public sections.

## Out of Scope

The following are intentionally out of scope for the first version:

- User accounts or login
- A database
- A content management system
- Public detailed roadmaps
- Public task lists
- Automated extraction from private vault to public website
- Full resume PDF workflow
